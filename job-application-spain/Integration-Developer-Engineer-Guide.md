## 🔧 What is an Integration Developer Engineer?

An **Integration Developer Engineer** specializes in connecting different systems, applications, and data sources. You act as the bridge between various technologies and platforms.

### Key Responsibilities

- Design and develop integration solutions between enterprise systems
- Implement API integrations (REST, SOAP, GraphQL)
- Work with middleware platforms (MuleSoft, IBM Integration Bus, Apache Camel)
- Develop ETL (Extract, Transform, Load) processes
- Ensure data consistency across systems
- Monitor and troubleshoot integration flows
- Document integration architectures and APIs
- Collaborate with multiple teams (DevOps, Backend, Frontend, DBA)

### Common Use Cases

- **ERP Integration**: SAP, Oracle, Microsoft Dynamics
- **CRM Integration**: Salesforce, HubSpot, Microsoft Dynamics CRM
- **Payment Gateway Integration**: Stripe, PayPal, Adyen
- **Cloud Services Integration**: AWS, Azure, GCP
- **Third-party API Integration**: External services and vendors
- **Data Synchronization**: Between databases and applications

## 🛂 Visa Sponsorship in Spain

### Work Visa Types for Spain

#### 1. **Highly Qualified Professional Visa (EU Blue Card)**

**Best option for tech professionals**

**Requirements:**
- University degree (Bachelor's or higher) OR 5+ years of professional experience
- Job offer with salary > €40,000/year (2024 threshold)
- Employment contract

**Benefits:**
- Valid for 1-2 years (renewable)
- Family members can join
- Path to permanent residence after 5 years
- Can change employers after 2 years

**Processing Time:** 1-3 months

#### 2. **General Work Permit (Autorización de Residencia y Trabajo)**

**Standard work visa**

**Requirements:**
- Job offer from Spanish employer
- Employer must prove no EU citizen can fill the position (labor market test)
- Employment contract

**Processing Time:** 2-4 months

#### 3. **Intra-Company Transfer Visa**

For employees of multinational companies transferring to Spanish office.

---

### Visa Sponsorship Process

**Step 1: Find Employer Willing to Sponsor**
- Many tech companies in Spain sponsor visas
- Explicitly mention in application: "Require visa sponsorship"

**Step 2: Employer Initiates Process**
- Employer files work permit application
- Provides employment contract
- Pays application fees

**Step 3: You Apply for Visa**
- Once work permit approved, apply at Spanish consulate
- Submit documents: passport, photos, medical certificate, criminal record
- Pay visa fees (~€60-80)

**Step 4: Arrival in Spain**
- Within 1 month of arrival, apply for TIE (Tarjeta de Identidad de Extranjero)
- This is your resident card

**Step 5: NIE Number**
- Número de Identidad de Extranjero
- Required for working, banking, renting
- Applied for with TIE

---

### Documents Needed

**From Your Side:**
- Valid passport (6+ months validity)
- University degree (translated + apostilled)
- Criminal background check (from your country)
- Medical certificate
- Passport photos
- Proof of health insurance
- Proof of accommodation in Spain

**From Employer:**
- Employment contract
- Company registration documents
- Proof of economic solvency
- Job description

## 🎯 Technical Interview Preparation

### Integration-Specific Questions

#### 1. **What is Enterprise Application Integration (EAI)?**

**Answer:**
EAI is the use of technologies and services to enable the integration of systems and 
applications across an enterprise. It ensures different applications can communicate 
and share data seamlessly.

**Key approaches:**
- Point-to-Point Integration
- Hub-and-Spoke (ESB)
- Message-Oriented Middleware
- API-led Connectivity

#### 2. **Explain Enterprise Integration Patterns (EIP)**

**Answer:**
EIPs are design patterns for enterprise integration. Common patterns include:

- **Message Channel**: Connects sender and receiver
- **Message Router**: Routes messages based on conditions
- **Message Translator**: Transforms message format
- **Content-Based Router**: Routes based on message content
- **Splitter**: Splits one message into multiple
- **Aggregator**: Combines multiple messages into one
- **Dead Letter Channel**: Handles failed messages

**Example in Apache Camel:**
```java
from("direct:orders")
    .choice()
        .when(simple("${body.amount} > 1000"))
            .to("direct:highValue")
        .otherwise()
            .to("direct:lowValue");
```

#### 3. **What is the difference between synchronous and asynchronous integration?**

**Answer:**

**Synchronous:**
- Request-response pattern
- Caller waits for response
- Example: REST API call
- Use when: Immediate response needed

**Asynchronous:**
- Fire-and-forget pattern
- Caller doesn't wait
- Example: Message queue (Kafka, RabbitMQ)
- Use when: Decoupling needed, long-running processes

#### 4. **Explain API-led Connectivity (MuleSoft concept)**

**Answer:**
API-led connectivity is a methodical way to connect data across applications through 
reusable APIs organized in three layers:

1. **System APIs**: Connect to core systems (databases, SaaS apps)
2. **Process APIs**: Orchestrate business processes
3. **Experience APIs**: Provide data optimized for specific channels

**Benefits:**
- Reusability
- Scalability
- Agility
- Easier maintenance

#### 5. **How do you handle errors in integrations?**

**Answer:**

**Error Handling Strategies:**

1. **Retry Mechanism**: Automatic retry with exponential backoff
```java
@Bean
public IntegrationFlow retryFlow() {
    return IntegrationFlows
        .from("inputChannel")
        .handle(service, s -> s
            .advice(retryAdvice()))
        .get();
}
```

2. **Dead Letter Queue**: Store failed messages for manual review
3. **Compensation/Rollback**: Undo changes if transaction fails
4. **Circuit Breaker**: Stop calling failing service
5. **Logging & Monitoring**: Track errors for analysis
6. **Alerting**: Notify team of critical failures

#### 6. **What is idempotency in integrations?**

**Answer:**
Idempotency ensures that processing a message multiple times has the same effect as 
processing it once. Critical for reliability.

**Implementation approaches:**
- Unique message IDs
- Deduplication at receiver
- Database constraints
- Idempotent API design (PUT vs POST)

**Example:**
```java
@PostMapping("/orders")
@Idempotent
public Order createOrder(@RequestHeader("Idempotency-Key") String key, 
                         @RequestBody OrderRequest request) {
    // Check if order with this key already exists
    if (orderRepository.existsByIdempotencyKey(key)) {
        return orderRepository.findByIdempotencyKey(key);
    }
    // Create new order
    Order order = new Order(request);
    order.setIdempotencyKey(key);
    return orderRepository.save(order);
}
```

#### 7. **Explain message transformation patterns**

**Answer:**

Common transformation patterns:

1. **Content Enricher**: Add additional data from external source
2. **Content Filter**: Remove unnecessary data
3. **Normalizer**: Convert different formats to canonical format
4. **Canonical Data Model**: Standard format for all integrations

**Example - DataWeave (MuleSoft):**
```dataweave
%dw 2.0
output application/json
---
{
    orderId: payload.order_id,
    customer: {
        name: payload.customer_name,
        email: payload.email
    },
    items: payload.items map (item) -> {
        productId: item.id,
        quantity: item.qty,
        price: item.price
    },
    total: sum(payload.items.*.price)
}
```

#### 8. **How do you ensure data consistency across systems?**

**Answer:**

**Approaches:**

1. **Two-Phase Commit (2PC)**: Distributed transaction
2. **Saga Pattern**: Compensating transactions
3. **Event Sourcing**: Store events, rebuild state
4. **Change Data Capture (CDC)**: Track database changes
5. **Eventual Consistency**: Accept temporary inconsistency
6. **Reconciliation Process**: Regular sync checks

**Example - Saga Pattern:**
```
Order Service: Create Order
    Success -> Payment Service: Process Payment
        Success -> Inventory Service: Reserve Items
            Success -> Complete
            Failure -> Compensate: Refund Payment, Cancel Order
        Failure -> Compensate: Cancel Order
```

#### 9. **What are your experience with API Security?**

**Answer:**

**Security measures:**

1. **Authentication**: Verify identity
   - OAuth 2.0
   - JWT tokens
   - API keys
   - Mutual TLS (mTLS)

2. **Authorization**: Verify permissions
   - RBAC (Role-Based Access Control)
   - Scopes in OAuth

3. **Encryption**: TLS/SSL for transport

4. **Rate Limiting**: Prevent abuse

5. **API Gateway**: Centralized security

6. **Input Validation**: Prevent injection attacks

**Example - JWT in Spring Boot:**
```java
@Configuration
@EnableWebSecurity
public class SecurityConfig extends WebSecurityConfigurerAdapter {
    
    @Override
    protected void configure(HttpSecurity http) throws Exception {
        http
            .csrf().disable()
            .authorizeRequests()
                .antMatchers("/api/public/**").permitAll()
                .anyRequest().authenticated()
            .and()
            .oauth2ResourceServer()
                .jwt();
    }
}
```

3. **Message Queue Monitoring**:

4. **Business Metrics**:

   - SLA compliance

**Tools:**

- Prometheus + Grafana
